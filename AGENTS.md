## App rules
- Dealer risk is owner-only, requested explicitly, persisted with its input facts, and generated by server-only AI Gateway Responses helpers; never let AI mutate blocking state.
- Dealer blocking uses an owner-confirmed database RPC and a sales insert trigger; retain payment collection and serialize blocks against sales using retailer-row locks.
- Only retailer-linked returns may influence dealer risk; flag unassigned return history as missing rather than attributing salesman returns to dealers.
- Stock, sale and return changes use validated database functions; owner-only audited history cancellation checks dependent stock/IMEI state. Never directly rewrite movements from the client.
- Salesman balances are derived from stock_movements, sales, retailer_payments and deposits (see src/lib/me.ts); do not store running totals.
- UI strings live in src/lib/i18n.tsx (Bengali + English pairs).
- Leaf page metadata uses the shared pageHead helper to keep company identity consistent with distinct page titles.
- Dashboard and stock counts use security-invoker reporting RPCs so totals aggregate in PostgreSQL without bypassing caller RLS.
- Shared queries reuse data briefly and mutations invalidate it; do not cache security decisions in browser storage.
- Blank letterhead settings fall back to the company defaults; explicit saved business settings remain editable.
- Dashboard insights use a security-invoker RPC; stock-house alerts are owner-only and retailer financial insights retain caller RLS.
- Age unallocated retailer payments against initial invoice balances oldest-first, ordered by sale timestamp and ID, without storing running balances.
- Daily and monthly reporting boundaries use the Asia/Dhaka timezone; per-product stock thresholds default to disabled until configured.
- Route guards and useMe read the session locally (getSession) and share the cached "me" query via meQueryOptions; RLS stays the enforcement layer, guards are UX-only.
- Do not enable tanstackStart autoCodeSplitting: it breaks hydration (MatchView "routeId" undefined) in this template.
- Offline support: the app-shell service worker is generated by vite-plugin-pwa (never hand-written) and registered only from src/lib/pwa-register.ts, which refuses dev/iframe/Lovable-preview contexts. Offline entries go through the localStorage queue in src/lib/offline.ts and replay through the same database functions on reconnect — queued entries are never applied optimistically. Last-fetched business data is persisted via src/lib/query-persist.ts; the "me" role query and dealer-risk queries are excluded (security decisions stay out of browser storage).
- Vercel builds switch Nitro to the 'vercel' preset only when VERCEL is set (vite.config.ts); default Cloudflare target stays for Lovable publishing.
- Settings business backups are owner-only atomic PostgreSQL snapshots of an explicit application-table allowlist; restore accepts unchanged same-installation exports only, preserves auth/audit/export history, and never reapplies dealer blocks or AI advice without fresh confirmation. Full database/account backups remain Cloud exports.
- Reset and restore require typed confirmation and a recent unchanged safety export; all destructive account corrections are owner-only audited RPCs, while retailer contact CRUD also permits its owning salesman.
- Offline replay is single-flight and removes only completed queue IDs so manual sync and reconnect cannot double-send or discard concurrently queued entries.
- User access uses protected user_roles plus user_permission_overrides; active status gates RLS and database mutation triggers, owner rights stay fixed, and confirmed role changes are serialized/audited with self-lockout prevention. Access queries are never persisted and identity refreshes periodically for UI revocation.
